SCOPECREEP
==========
Infrastructure / Recovery / Service Overview
Snapshot date: 2026-09-28
Updated through direct DN42 edge peering, controlled full-table transit for iEdon, policy routing, and 50 Mbps peer rate limiting.

PURPOSE
-------
ScopeCreep is Kyle's secondary always-on Debian VPS. It acts as a backup
peer/storage host, monitoring-agent host, Docker utility host, WireGuard node,
DN42 internal router, and secondary authoritative DN42 DNS server.

ScopeCreep is DN42 edge/router #2 for AS4242420425. In addition to its
dedicated WireGuard/iBGP core to Clanker, it now has three direct external
eBGP peers: iEdon (Dallas), Kioubit (Los Angeles), and MOE233 (Las Vegas).

ScopeCreep also provides controlled IPv4 and IPv6 DN42 transit to iEdon. The
transit design uses a separate BIRD routing view and Linux policy-routing table
that excludes routes learned directly from iEdon, so traffic arriving from
iEdon is forwarded through an alternate peer instead of hairpinning back to
iEdon. The iEdon peer is capped at 50 Mbps in both directions.

This file is intended to answer:
- What is ScopeCreep?
- What runs here?
- What starts it?
- Where is persistent data?
- What backup responsibilities does it have?
- Which secrets/configuration matter for recovery?
- What networks does it participate in?
- What would be needed to rebuild it?
- What have we not inventoried yet?

It is deliberately broader than a backup manifest.

IEDON TRANSIT ROUTING VIEW
--------------------------

BIRD tables:
    iedon_transit4
    iedon_transit6

BIRD protocols:
    iedon_transit_pipe4
    iedon_transit_pipe6
    iedon_transit_kernel4
    iedon_transit_kernel6

Linux kernel routing table:
    2190

Design:
    master4/master6
        -> pipe every route except routes whose source protocol is iedon_dal
        -> iedon_transit4/iedon_transit6
        -> kernel table 2190

Linux policy rules:
    priority 21880
    from all iif wg-dn42-iedon lookup 2190

This allows traffic arriving from iEdon to use the best alternate path through
Kioubit, MOE233, or Clanker instead of selecting a route learned directly from
iEdon and hairpinning it back to the same peer.

Persistence:
    /etc/systemd/system/dn42-iedon-transit-policy.service
    enabled
    active (oneshot/exited)

RATE LIMIT
----------

The complete wg-dn42-iedon interface is capped at 50 Mbit/s in both directions.
This includes transit plus BGP/health/keepalive traffic on that interface.

Egress ScopeCreep -> iEdon:
    tc TBF
    rate 50mbit
    burst 256kb
    latency 50ms

Ingress iEdon -> ScopeCreep:
    tc clsact ingress filter
    matchall police
    rate 50mbit
    burst 256kb
    conform-exceed drop

Persistence:
