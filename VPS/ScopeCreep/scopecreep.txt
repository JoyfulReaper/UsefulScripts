PURPOSE
-------
ScopeCreep is Kyle's secondary always-on Debian VPS. It acts as a backup
peer/storage host, monitoring-agent host, Docker utility host, WireGuard node,
DN42 internal router, and secondary authoritative DN42 DNS server.

ScopeCreep is DN42 edge/router #2 for AS4242420425. In addition to its
dedicated WireGuard/iBGP core to Clanker, it now has three direct external
eBGP peers: iEdon (Dallas), Kioubit (Los Angeles), and MOE233 (Las Vegas).

ScopeCreep provides controlled IPv4 and IPv6 DN42 transit to iEdon and
Kioubit. Each transit peer has a separate BIRD routing view and Linux
policy-routing table. Third-party routes learned from the ingress peer are
excluded from that peer's return view, while AS-path-length-1 directly
originated prefixes remain reachable over the direct session. Both transit
peer interfaces are capped at 50 Mbps in each direction.

This file is intended to answer:
- What is ScopeCreep?
- What runs here?

- What backup responsibilities does it have?
- Which secrets/configuration matter for recovery?
- What networks does it participate in?
- What would be needed to rebuild it?
- What have we not inventoried yet?

It is deliberately broader than a backup manifest.

External export policy:
    MOE233 retains the normal own-prefix-only export policy.

    iEdon and Kioubit are explicit controlled-transit peers. Their IPv4/IPv6
    channels use sorted BIRD master tables plus `secondary on`, allowing BIRD
    to advertise an alternate candidate when the selected best route was
    learned from that same peer and is rejected by the export filter.

    Both full-table export filters:
        - always export AS4242420425's own registered prefixes
        - reject paths already containing the destination peer ASN
        - reject standard NO_EXPORT / NO_ADVERTISE communities
        - export other valid DN42 routes

IEDON TRANSIT ROUTING VIEW
--------------------------

BIRD tables:
    iedon_transit4
    iedon_transit6

BIRD protocols:
    iedon_transit_pipe4
    iedon_transit_pipe6
    iedon_transit_kernel4
    iedon_transit_kernel6

Linux kernel routing table:
    2190

Design:
    master4/master6
        -> copy alternate routes into iedon_transit4/iedon_transit6
        -> reject third-party routes learned through iedon_dal
        -> preserve iEdon routes with AS-path length 1 so directly originated
           iEdon prefixes remain on the direct session
        -> kernel table 2190

Linux policy rules:
    priority 21880
    from all iif wg-dn42-iedon lookup 2190

This allows traffic arriving from iEdon to use the best alternate path through
Kioubit, MOE233, or Clanker for third-party destinations without using iEdon
as its own transit provider. Prefixes directly originated by iEdon remain
reachable over the direct iEdon session.

Persistence:
    /etc/systemd/system/dn42-iedon-transit-policy.service
    enabled
    active (oneshot/exited)
