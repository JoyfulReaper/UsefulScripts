SCOPECREEP
==========
Infrastructure / Recovery / Service Overview
Snapshot date: 2026-09-27
Updated through DN42 router/core/iBGP and secondary authoritative DNS deployment.

PURPOSE
-------
ScopeCreep is Kyle's secondary always-on Debian VPS. It acts as a backup
peer/storage host, monitoring-agent host, Docker utility host, WireGuard node,
DN42 internal router, and secondary authoritative DN42 DNS server.

ScopeCreep is now being developed as DN42 edge/router #2 for AS4242420425.
It currently reaches the wider DN42 network through Clanker over a dedicated
WireGuard core and iBGP. A direct external DN42 eBGP peer is the next major
routing step.

This file is intended to answer:
- What is ScopeCreep?
- What runs here?
- What starts it?
- Where is persistent data?
- What backup responsibilities does it have?
- Which secrets/configuration matter for recovery?
- What networks does it participate in?
- What would be needed to rebuild it?
- What have we not inventoried yet?

It is deliberately broader than a backup manifest.

11. BACKUP ARCHITECTURE
===============================================================================

ScopeCreep backs itself up to Clanker over the private WireGuard network.

Destination:
    rest:http://10.99.0.1:8000/scopecreep/

ScopeCreep also hosts Clanker's peer restic repository:
    /var/lib/restic/clanker

Backup staging:
    /var/lib/vps-backup/staging

Secret files:
    /etc/vps-backup/

These are intentionally excluded from the normal peer backup and must be
preserved out-of-band.

Important persistent/rebuild-relevant data:
    /var/lib/restic
    /opt/dockge/data
    /opt/stacks
    /opt/stacks/beszel-agent/beszel_agent_data
    /etc/missioncontrol-agent.env
    /etc/wireguard
    /etc/bird
    /etc/nsd
    /etc/systemd/system

The new DN42 configuration is covered by normal /etc backup except for any
out-of-band secrets excluded by policy.

13. RESTORE ORDER
===============================================================================

Suggested high-level rebuild order:

1. Provision Debian 13 or compatible successor.
2. Restore SSH/admin access.
3. Restore public networking.
4. Install WireGuard, BIRD, NSD, Docker/Compose, UFW, and required utilities.
5. Restore private wg0 and other required WireGuard configuration.
6. Restore wg-dn42-core configuration.
7. Enable/start:
       wg-quick@wg-dn42-core
8. Verify:
       192.168.252.2/30
       fe80::425:2/64
       Clanker core reachability
9. Restore:
       /etc/systemd/system/dn42-loopback.service
10. Enable/start dn42-loopback.service.
11. Verify loopback:
       172.20.220.51/32
       172.20.220.52/32
       fdf0:e12c:5528::51/128
       fdf0:e12c:5528::52/128
12. Restore BIRD configuration and start bird.service.
13. Verify:
       clanker_core Established
       clanker_core_v6 Established
       DN42 route tables populated
       only intended local /32 and /128 routes originate toward Clanker
14. Restore NSD configuration and start nsd.service.
15. Verify AXFR/NOTIFY from Clanker.
16. Verify authoritative answers over .51 and ::51.
17. Restore Docker / Compose projects.
18. Restore /var/lib/restic before exposing rest-server.
19. Restore Dockge/Beszel state.
20. Republish Mission Control Agent and restore its EnvironmentFile.
21. Restore backup timers and out-of-band backup secrets.
22. Verify ScopeCreep self-backup to Clanker.
23. Verify Clanker's repository hosted on ScopeCreep.
24. Perform representative restore tests.
