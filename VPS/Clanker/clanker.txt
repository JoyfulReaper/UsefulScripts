PURPOSE
-------
Clanker is Kyle's primary always-on Ubuntu VPS. It currently acts as a mixed
application host, protocol server, VPN/router, observability node, Yggdrasil
overlay node, DN42 router, reverse-proxy host, authoritative DNS host, local
recursive/caching resolver, and backup peer/storage node.

This file is intended to answer:
- What is Clanker?
- What runs here?
- What starts it?
- Where is its configuration?
- Where is persistent data?
- Which secrets and identities matter for recovery?
- What networks does it participate in?
- What backup responsibilities does it have?
- What would be needed to rebuild it?
- What remains worth documenting or cleaning up?

It is deliberately broader than a backup manifest.

Important DN42 firewall lesson:
    A working WireGuard handshake does NOT prove BGP can establish.

    RoutedBits and Baragoon initially worked because Clanker initiated their TCP
    BGP sessions and the replies matched ESTABLISHED/RELATED state.

    HEADSCARF175 initiated TCP/179 toward Clanker. UFW's default deny policy
    silently dropped those new inbound SYNs until an interface-specific BGP rule
    was added for wg-dn42-hs1.

    Prefer interface-specific TCP/179 rules for DN42 peer interfaces rather than
    opening BGP globally.

Docker forwarding/address-space note:
    Docker was moved away from DN42 address space after automatic bridge networks
    occupied parts of 172.20.0.0/14.

    Current automatic Docker address-pool strategy uses:

ROA validation:
    BIRD contains dedicated DN42 ROA tables:

        roa4 table dn42_roa
        roa6 table dn42_roa_v6

    Generated files:
        /etc/bird/roa_dn42.conf
        /etc/bird/roa_dn42_v6.conf

    Update helper:
        /usr/local/sbin/update-dn42-roa

    Repository copy:
        /home/joyfulreaper/UsefulScripts/VPS/Clanker/update-dn42-roa.sh

    The updater:
        - downloads current generated IPv4/IPv6 DN42 ROA tables
        - performs a route-count sanity check
        - compares new tables byte-for-byte with current copies
        - skips BIRD reload when both are unchanged
        - validates BIRD configuration before applying changed tables
        - restores previous files if validation/reload fails

    Origin validation is enforced on imported DN42 routes.

    NOTE:
        ROA validation verifies the authorized route origin. It does not validate
        every ASN in the complete AS path and does not prevent every possible
        route leak or policy mistake.
